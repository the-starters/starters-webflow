# Edit Profile v3 test bundle

This folder isolates the first-party scripts used by `/starter-edit-profile-test` from the production script paths. `runtime/` preserves their original relative paths so the page can later point at one immutable bundle ref. The baseline is the exact versions currently pinned on the test page: `v1.59.607` for the profile controllers and `v1.59.614` for the Work Experience rows and accordion. `manifest.json` records each source tag and byte hash, in the page's load order. Its bytes are bundle-only and carry no `@release` marker of their own. Where a materialized file still shows an `@release` banner it was inherited from the baseline tag and is historical: it names the published bytes the copy started from, not the patched bytes in `runtime/`. Only the `sha256` in `manifest.json` identifies those. `python3 materialize.py` rebuilds the complete local `runtime/` from those immutable tags plus `patches/work-experience-month-picker.patch`; `python3 verify.py` checks the resulting files. The full runtime files are present locally but ignored by Git because copied legacy scripts contain service hostnames. The tracked manifest and patch preserve the bundle for later reconstruction without recommitting those hosts.

`original-page-pins.json` records the exact first-party versions loaded by the existing non-test `/starter-edit-profile` page as read from Webflow on 2026-09-23. It is an external-pin readback and is not the same observation as `v3/starter-edit-profile/live-body-provenance.json`, which hashed inline body embeds on that page on 2026-08-12; the file's `relatedRecords` states how the two differ. Those tagged Git objects preserve the working original code for future changes without a separate legacy folder. Run `python3 edit-profile-v3/materialize_original.py <empty-output-dir>` to reconstruct that mixed-version snapshot when needed. Its Portfolio CRUD pin is `v1.59.615`, which includes the recent Work Highlights hotfix. The original page and its script pins have not been changed by this bundle. The original source paths in Git also remain untouched; their current files are not necessarily byte-identical to the older versions pinned by Webflow.

The proposed Work Experience month-picker change and two critical follow-up fixes belong only in this bundle: wrapping labels cannot remove date inputs, and the unified section remains the sole owner of its date-range error message. No Webflow page has been repointed or published by creating this folder. The live `/starter-edit-profile` route remains on its existing scripts. The test page's authored Webflow layout, calendar icon elements, authentication helper, and sitewide scripts remain in Webflow; they are not duplicated here. `contracts/` holds the row fixture used to verify the page-specific scripts by hand in a browser. The published form contract is not copied here; `v3/starter-edit-profile/published-form-contract.json` remains its single definition.

`work-experience-month-picker.test.js` rebuilds the four Work Experience scripts from the tracked sources and `patches/`, refuses to run unless the result still matches the bytes `manifest.json` pins, and then exercises that code: month selection and `YYYY-MM` serialization, retained saved dates, the end-date minimum, removal teardown, and the wrapping-label guard. It needs no tags, network or Python, so it cannot hold up the repository's other tests. The `starter-edit-profile.js` overlay is outside it — that file's pinned `v1.59.607` copy is not the one on this branch, so only `materialize.py` and `verify.py`, which read every entry from its tag, cover it. The company controller has changed since this bundle was pinned. The test first reverses the tracked profile-save-feedback delta, then applies the month-picker patch; the historical manifest remains unchanged. The test page currently loads the image-auth shim and profile-photo script twice; the controllers are guarded against duplicate initialization. No page-install snippets are kept here — write them when a cutover is authorized and the materialized runtime is deliberately included in a release artifact.

Before any page cutover, verify every script in `manifest.json`, the authored Webflow attributes, and the Work Experience save/reload flow on the disposable test account. Do not overwrite the user's unsaved browser tabs. The mobile accordion resize issue remains parked.
